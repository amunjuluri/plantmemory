# Evaluation results

Generated by `make eval` on 2026-10-12. **All data is synthetic** (52 incidents in memory, 30 reports that should find one, 16 that should not, 13 of them look-alikes). Gemini model `gemini-3.8-flash`, embeddings `gemini-embedding-2` (768 dims).

## 1. What the app tells the user

Each report goes through the live agent's steps: Gemini structures it and memory is searched. Records scoring at least 0.7 are candidates. The app then asks Gemini to check each candidate and shows only those it confirms as the same problem; code ignores any id that was not a candidate.

| Measure | Score only | Score + Gemini check (live) |
|---|---|---|
| Found the right past incident (shown first) | 28/30 (93%) | 30/30 (100%) |
| Found every earlier record of it (so the repeat count is right) | 30/30 (100%) | 28/30 (93%) |
| Missed it (said nothing similar) | 0/30 (0%) | 0/30 (0%) |
| Showed at least one wrong record alongside | 30/30 (100%) | 0/30 (0%) |
| **False alarm**: said it happened before when it had not | 15/16 (94%) | 0/16 (0%) |
| False alarm on look-alikes | 13/13 (100%) | 0/13 (0%) |

## Limits

- Everything is synthetic. Records and test reports were written for this project, in English, for two industries (paper and pharma).
- The same team wrote the records, the test reports and the prompt that checks candidates. The prompt states general rules and names none of the test cases, but results on reports written by someone else may be lower. A useful next step is a held-out set written by a plant engineer who has not seen the prompt.
- 46 test reports is small: one wrong answer moves a rate by 2 to 6 points.
- Gemini's answers vary slightly between runs; we ran the full eval three times on 10 Oct 2026 and got the same rates each time.
